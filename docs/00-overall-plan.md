# 00 — AeroPatch: Overall Plan (Revised after Deep Review, 2026-09-24)

This is the entry point. It gives the verdict, the decisions, the revised 4-week plan on one
page, and an index of every category document. Each category doc is about 150 lines. Topics
too big for one file are split into `-part1` / `-part2`.

## 1. Verdict

The idea is sound and mirrors proven designs (Agentless; the AIxCC finalists Atlantis and
Buttercup). The plan needs **five corrections** to be feasible and credible:

1. **Hardware**: this laptop has an RTX 3050 with **4 GB VRAM** and 16 GB RAM, and no Python
   is installed. Local 3–4B training won't fit. **Train on a free Kaggle/Colab T4; infer
   locally** with a Q4 GGUF via llama.cpp/Ollama. vLLM and AWQ are dropped.
2. **Outdated models**: **Gemini 2.0 Flash was shut down on 2026-06-01**.
   **Qwen2.5-Coder-3B is non-commercial** (Qwen Research License). Newer Apache-2.0 small models
   exist: **Qwen3.5-4B** (Mar 2026) and Gemma 4 E2B/E4B (Apr 2026).
3. **Evaluation first**: build the 40–50-scenario benchmark and baselines in Weeks 1–2, so
   the fine-tuning delta can be measured. The original plan builds it in Week 4.
4. **Edit format**: the model emits **search/replace blocks** and the harness computes the
   unified diff. Raw diffs are the most avoidable failure mode for small models.
5. **Claims**: "comparable to frontier" and "75% within 2 iterations" are targets, not results.
   Resume numbers come only from measured runs, reported with confidence intervals.

## 2. Decision table

| Decision | Choice | Rationale (doc) |
|---|---|---|
| Primary local model | **Qwen3.5-4B**, LoRA 16-bit (Unsloth advises against QLoRA on Qwen3.5) | Newest Apache-2.0 small model; fits 4 GB at Q4 (03) |
| Laptop-trainable demo | Qwen2.5-Coder-1.5B-Instruct, QLoRA | Only credible "trained on a 4 GB GPU" claim (03, 10) |
| Fallback model | Qwen2.5-Coder-3B-Instruct, QLoRA (note non-commercial license) | If Qwen3.5 tooling fails (03) |
| Frontier fallback | One provider in the router; default Claude model `claude-opus-5`; cheaper tier is your choice | Less code; refusal-aware routing (04) |
| Gemini | Optional *benchmark reference* only (current Flash, e.g. 3.7/3.8) | 2.0 Flash retired (04) |
| Training compute | Kaggle T4 (≈30 GPU-h/week), Colab as backup | 4 GB VRAM locally (02, 10) |
| Serving | llama.cpp `llama-server` or Ollama, GGUF Q4_K_M (Q5/Q8 ablation) | Runs on the 4 GB laptop GPU; vLLM needs far more memory (10) |
| Orchestration | Plain Python state machine (~120 LOC); no LangGraph | 6 states, JSONL resume (08) |
| Model role | Pure function: context → edit. No tools, no shell | Small-model reliability and injection resistance (05, 13) |
| Edit format | RATIONALE + SEARCH/REPLACE blocks; diff generated by `git diff` | Small models fail on hunk math (08) |
| MCP | Thin wrapper (spec 2026-07-28, stateless, stdio) over plain functions; no commit/push tools | External interface and demo (06) |
| Static analysis | tree-sitter (context) + stdlib `ast` (syntax gate) + Opengrep + Bandit; own ruleset | Licensing and accuracy (06) |
| Sandbox | Hardened runc on Docker Desktop/WSL2: no network, read-only, cap-drop ALL, limits; two-phase build | No gVisor on Desktop for Windows (07) |
| Benchmark | 25–30 hand-built CWE scenarios + 10–15 Python CVEs (Vul4Py, PatchEval-Verified, CVE-Bench) + 5 held-out synthetic + 4–6 adversarial | Contamination control and scope (11, 13) |
| Metrics | pass@k (unbiased, no feedback) *and* resolve@k (with repair); Wilson CIs; McNemar | The plan conflated the two (12) |
| PR policy | Human-approved **draft** PRs to **your own demo repos**; never auto-merge | Outward-facing action (08, 13) |

## 3. Revised 4-week plan (one page)

| Week | Focus | Exit criteria |
|---|---|---|
| **W1** | Environment (WSL2, `uv`, Docker, Ollama), hardened sandbox, 10 dev scenarios, context extraction + scanners, edit engine, single-shot pipeline, **baselines** for 2–3 models | One command resolves a scenario; baseline table exists; sandbox security tests pass |
| **W2** | Repair loop, full gates, router modes, **40–50 validated scenarios** (split frozen), benchmark runner + metrics v1, thin MCP wrapper, **full baselines with repair** | Unattended resumable benchmark; baseline table with CIs; failure attribution |
| **W3** | Dataset (synthetic CWE injection + MoreFixes + SWE-smith/Gym, repair turns, leakage checks), Kaggle LoRA (pilot → full), GGUF export, local serving, dev eval | Fine-tuned Q4 model served locally; dev delta vs untuned |
| **W4** | Final test runs, pass@5, ablations (quant, grammar, localization, thinking), charts/stats, compose, README, MCP demo, security checklist, resume bullets from measured numbers | Every number traceable to a run file; repo safe to publish |

Critical path: **environment → sandbox → scenarios → baseline → dataset → training → final eval.**
If you slip, use the cut list in [14-timeline-part2.md](14-timeline-part2.md). Never cut the
sandbox tests, the gates, the scenario validator, the baselines, or traceable numbers.

## 5. Top risks at a glance (full register in 14b)

| Risk | Mitigation |
|---|---|
| Scenario authoring is slower than planned (the real long pole) | Start on D3; accept 30 scenarios; drop Tier C first |
| Too few verified training examples | Synthetic CWE injection from D14; MoreFixes + SWE-smith as backup |
| Qwen3.5 tooling issues (GGUF, llama.cpp build) | Fall back to Qwen2.5-Coder-3B QLoRA, with the license noted |
| Fine-tuned model not better | Baselines exist from W1, so an honest null result is still a result; check train/inference parity |
| Frontier refusals on security text | Treat as routing events; server-side fallbacks; report refusal rate |

## 7. One-line summary for the README

> AeroPatch asks how much automated vulnerability remediation a 4B model on a 4 GB laptop GPU
> can do: it fixes Python vulnerabilities locally, proves each fix in a network-less sandbox,
> retries with test feedback, and escalates to a frontier model only when needed, with every
> claim measured on a contamination-controlled benchmark.
