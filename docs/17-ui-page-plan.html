AeroPatch · doc 17 Phase 2 · plan, version 2 · for your approval

A local page that finds, fixes and explains, live

Paste a folder or a GitHub link and press Check. Tick the problems you want fixed. Watch the local model plan each fix, the safety gates judge it and the sandbox test it, step by step. If the local model gives up, hand that one problem to Claude or any AI tool you like, after seeing exactly what would be sent.

            How it fits together
            
    
            One small Python server, started by uv run aeropatch ui, with no new packages. It drives the same check, fix loop, gates and sandbox the command line uses. Benchmark configs keep their meaning.
            
  
            

  

  
            One fix, step by step
            
  
              
    
            1. What it reads. AeroPatch cuts out the function around the problem and the lines it needs, at most about 6,000 tokens. The model never sees the whole project.
              2. 
    
            2. The model writes. Ollama streams the answer to the page as it is written: a one-line plan, then the edit as search-and-replace blocks. With “Show thinking” on, its reasoning streams first.
              3. 
    
            3. 8 safety gates. Plain code, no AI. The edit must change something and stay small. It must leave tests, config and dependency files alone and touch only the files it was shown. No “ignore this warning” comments, valid Python, no deleted functions, no risky imports. A failed gate stops the try before anything runs.
              4. 
    
            4. Sandbox. Your own tests run on a copy, with the network off and your code read-only. Each test result shows as it comes in. The first fix in a project builds the sandbox first. That can take several minutes, and the page shows its progress.
              5. 
    
            5. Re-scan. The scanner runs again on the changed file to see if the warning is gone.
              6. 
    
            6. Result or next try. If it passes, the page shows the label and how often that label was right on AeroPatch's benchmark. If not, the page shows exactly what the model is told before trying again. After 3 tries, or if it repeats itself, the hand-off panel opens.
              7. 
  
            

  
            
    
            
      
            RequestWhat it does
            
      
        
            GET /api/doctorThe status strip: which levels are ready.
            
        
            POST /api/choose-folderOpens the Windows folder dialog and returns the path.
            
        
            POST /api/checkChecks a folder or link. Returns a job number.
            
        
            POST /api/fixFixes the ticked problems, one after another. Returns a job number.
            
        
            GET /api/job/<id>?since=NEvery event after event N: steps, streamed text, gate and test results. Polled every second.
            
        
            GET /api/handoff/<n>The exact text that would be sent for problem n, after the secrets check.
            
        
            POST /api/handoffSends problem n to Claude or another local model. Its answer goes through the same gates and sandbox.
            
        
            POST /api/answerChecks an answer you pasted from another AI tool, as one more try.
            
        
            POST /api/apply, /api/undoWrites a fix into the folder after a backup, or puts the exact old file back.
            
        
            GET /api/patch/<n>The fix as a .patch file, for GitHub links where there is no folder of yours to write to.
            
                  
    
            
  
            

            



            
  
            
    
            What the live view can and cannot show
            
    
            Everything on it comes from the real run as it happens. Nothing is animated for show.
            
  
            
  
            
    
            
      
            Shown live
            
      
              
        
            • The exact text the model was given, and its size.
              • 
        
            • Its answer as it is written, with speed (about 46 tokens a second on this laptop) and time.
              • 
        
            • Each gate's verdict, and each test as it passes or fails.
              • 
        
            • Whether the scanner still sees the problem.
              • 
        
            • The exact feedback for the next try, and every earlier try to click back to.
              • 
        
            • The full text sent in a hand-off, and the answer that came back.
              • 
      
            
    
            
    
            
      
            Only with a switch, or not at all
            
      
              
        
            • The local model's thinking shows only with “Show thinking” on. The labels' hit rates were measured with it off. On the benchmark, thinking on fixed 41 of 54 against 38, which was under the bar set in advance.
              • 
        
            • Claude's reasoning is not returned by Claude Code. The page shows what was sent and the answer.
              • 
        
            • A GitHub link has no tests of yours inside the sandbox unless the repo ships them. The label then says “not tested”.
              • 
      
            
    
            
  
            

            



            
  
            
    
            Kept safe
            
    
            The checks from version 1 stay. The ones outlined in blue are new for fixing and hand-off.
            
  
            
  
            
    
            Nothing leaves without a click
            A hand-off first shows the exact text. A secrets check blocks any request that looks like it holds a key or password.
            
    
            Your subscription, not an API key
            Claude is reached through your Claude Code login. AeroPatch removes any API key from the call, so nothing is billed per word.
            
    
            Pasted answers get no shortcut
            An answer from any AI tool goes through the same 8 gates and the same sandbox as the local model's.
            
    
            The sandbox is shut tight
            Network off, your code read-only, a normal user with every special right dropped. 2 GB, 2 CPUs, 256 processes, 5 minutes.
            
    
            Nothing written before Apply
            Apply backs up each file first and refuses if the file changed since. Undo puts back the exact bytes. No commit, push or pull request, ever.
            
    
            Laptop only, with a key
            Listens on 127.0.0.1. Every request needs the launch token, the right host and no foreign origin.

            What the section shows
            
      
              
        
            • Each provider with its state: “ready”, “key missing”, or “local server not answering”.
              • 
        
            • A field to add a key, a model list read from the provider, and a Test button that sends one tiny request.
              • 
        
            • The models you have set up then appear as choices in the hand-off panel.
              • 
      
            
    
            
    
            
      
            Rules for paid models
            
      
              
        
            • Off until you add a key. Local stays the default for every first try.
              • 
        
            • A key is saved only in F:\AeroPatch\.env on this laptop, which git ignores. The page never shows it again, only its last 4 characters.
              • 
        
            • A key is only ever sent to its own provider's fixed address. A custom address must be https, or localhost.
              • 
        
            • Before each paid send: the exact text, its size, and the estimated cost where AeroPatch knows the price. A per-problem spending cap applies, $0.50 by default.
              • 
        
            • The secrets check runs on every route, paid or free.

            1. 1Page, status strip, folder picker, check with live stepssmallMostly drafted. Works on any laptop, no Ollama or Docker needed.

              3. 
    
            3. 3Hand-off and the Models sectionlargeClaude Code, any AI tool, other local models, and paid or open-source model APIs from the Models section. Preview, the secrets check, cost before each paid send, continuing the history, and checking a pasted answer.
              4. 
    
            4. 4Apply, Skip, Undo, .patch download; READMEsmallWires up code that exists, then a full run on one real public repo.
